This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Setup
python3.11 -m venv .venv && pip install -e ".[dev]"

# Validate YAML schemas + cross-references (runs in CI on every PR)
python scripts/validate.py

# Build all artifacts: dist/flous.sqlite, dist/flous-data.json, dist/types.ts
python scripts/build.py

# Lint
ruff check schemas/ scripts/

# Type check
mypy schemas/ scripts/

# Tests
pytest
pytest tests/path/to/test_file.py::test_name   # single test
```

## Architecture

**Source of truth is YAML** — never edit `dist/` directly; it is always regenerated by `scripts/build.py`.

### Data flow

```
data/banks/*.yaml          ─┐
data/accounts/*.yaml        ├─ scripts/build.py ─► dist/flous.sqlite
data/features.yaml         ─┘                   ─► dist/flous-data.json
                                                 ─► dist/types.ts
```

`scripts/validate.py` runs first in CI and enforces:
- Pydantic schema correctness (`schemas/`)
- Feature codes referenced in accounts must exist in `features.yaml`
- Bank slugs referenced in accounts must exist in `data/banks/`
- `value_type` on a Feature must match which field is populated in `AccountFeature` (e.g. `money_fixed` → `value_money` required)

### Key design decisions

**Polymorphic values**: `AccountFeature` has five nullable value columns (`value_money`, `value_bool`, `value_text`, `percentage`, `free_quota`/`unit_cost`). Which ones are populated is determined by `Feature.value_type`. The Pydantic validator in `schemas/account.py` enforces consistency at load time.

**Conditional pricing**: `FeaturePrice` rows attach to an `AccountFeature` and express discount conditions (e.g. "free with salary credit ≥ €1000"). An account with no conditions simply has an empty `conditions` list.

**Historical versioning**: `account_features.effective_from` / `effective_to` support time-series. `effective_to IS NULL` = current value. When updating a value, set `effective_to` on the old row and insert a new one. The build script currently writes `effective_to=NULL` for all rows (first-time load).

**Deterministic builds**: `scripts/build.py` sorts all collections by slug/code before writing, so the same YAML input always produces identical output bytes.

### Packages

- `packages/flous_data/` — Python package published to PyPI. Bundles `dist/flous.sqlite` and exposes SQLAlchemy ORM models (`db.py`). Call `get_session()` for a ready-to-use session.
- `packages/flous-data-js/` — npm package `@flous/data`. Bundles `dist/flous-data.json` and re-exports typed helpers (`getBanks()`, `getAccounts()`, etc.).

### CI workflows

- `pr-validate.yml` — runs `validate.py` + ruff + mypy on every PR and push to main.
- `build-publish.yml` — on merge to main: builds artifacts, uploads `dump.json` to Cloudflare R2 (`data.flous.it/v1/dump.json`), triggers `flous-api` webhook. On release tag: publishes to PyPI (OIDC trusted publishing) and npm.

### Secrets required (GitHub Actions)

| Secret | Used by |
|--------|---------|
| `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_ENDPOINT` | CDN publish step |
| `FLOUS_WEBHOOK_URL` / `FLOUS_WEBHOOK_SECRET` | `flous-api` refresh trigger (HMAC SHA256) |
| `NPM_TOKEN` | npm publish |

PyPI publish uses OIDC (no token needed, configure trusted publisher on PyPI).

## Adding data

**New bank**: add `data/banks/{slug}.yaml` matching `schemas/bank.py` (id, name, slug, bic, abi, mec_code, country).

**New account**: add `data/accounts/{slug}.yaml` matching `schemas/account.py`. Use existing feature codes from `features.yaml`; only add new ones to `features.yaml` first.

**New feature**: add to `features.yaml`, then reference from accounts. Adding a feature is a **minor** semver bump; renaming/removing is **major**.

## Versioning policy

| Change | Bump |
|--------|------|
| Data update (fee change, new condition) | patch |
| New feature in catalog | minor |
| Schema change (rename, new required field) | major |
